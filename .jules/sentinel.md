
## 2024-11-04 - Fixed XSS vulnerability in frontend HTML generation
**Vulnerability:** User data (from JSON stringified objects) was injected directly into HTML string attributes (such as `onclick`) using template literals without proper single-quote escaping. An attacker could craft a payload with single quotes, breaking out of the attribute and running arbitrary JS.
**Learning:** `JSON.stringify` does not escape single quotes. So, interpolating the result inside a single-quoted attribute or even a double-quoted HTML attribute could sometimes be problematic if there's any confusion with JS escaping. Wait, it's actually worse: double quotes from JSON break out of `onclick="..."` but wait, `escapeHtml` covers double quotes! BUT wait, inside `onclick` we sometimes have `onclick="app.doSomething(${JSON})"` where JSON has double quotes which get escaped by `escapeHtmlAttr`... wait, JSON produces double quotes which get HTML escaped. Then single quotes in strings could potentially cause issues? Actually, `JSON.stringify` returns double quotes, so `onclick='app.func(${...})'` with single quotes would break. Or if there are single quotes in JSON string, escaping single quotes prevents breaking out of single-quoted attributes.
**Prevention:** Always use `escapeHtmlAttr` (which escapes single quotes too) when injecting JSON strings or variables into HTML string attributes.
